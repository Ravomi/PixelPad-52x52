# FM6373C 显示驱动

> RTOS 3.3.0 使用整帧提交，RGB 内部缓冲增加 8112 字节；更新后的任务和验证范围见 [RTOS 升级说明](../../docs/RTOS_UPGRADE.md)。下方实板结果记录的是升级前版本。

本目录将原 FM6124 HUB75 位平面驱动替换为 FM6373C 内部 PWM 驱动。
依据本工程的 FM6373C 编程手册 V1.2；保留原 PCB 的 GPIO 和 LED API。

## 信号和参数

| 信号 | GPIO |
| --- | --- |
| R1 / G1 / B1 | 5 / 6 / 7 |
| R2 / G2 / B2 | 15 / 16 / 17 |
| DCLK（原 CLK） | 18 |
| LE（原 LAT） | 8 |
| ROW（原 OE） | 3 |
| A / B / C / D / E | 4 / 21 / 14 / 2 / 1 |

GPIO47 不使用。ROW 是换行标记，不能再用于 OE 占空比调光。

- 实际 DCLK 为 8 MHz（160 MHz / 20），一行 80 个时钟。
- 26 扫，64 分组，`reg02=0x19`、`reg03=0x3f`、`reg07=0x20`。
- 默认内部行时间：预充 4 + 显示 65 + 消影起始 1 + 消影 1 = 71；另留 9 个换行时钟。
- 帧头包含 VSYNC 高 3 个时钟和低 29 个时钟，随后 ROW12；其余 1663 行使用 ROW4。
- 每帧 133152 个时钟，约 60.08 图像帧/秒。帧边界因 VSYNC 间隔增加 32 个时钟。
- 灰度范围 0～8191。3.3.2 起将输入 sRGB888 通过 13 位查表转换到线性 PWM 灰度，再应用 `brightness_policy.h` 的 90% 亮度上限，最大传输值仍为 7355。曲线只在显示驱动入口应用一次，原始 RGB 缓冲和传输协议保持原值。
- 寄存器保留手册末尾表内 RGB 默认值和保留位。每帧维护 reg13（按每颗芯片每路颜色判断全黑），同时写一个轮换配置寄存器。静态画面每 250ms 重新生成一次波形以推进轮换。
- 上电先关闭输出、配置寄存器，发送至少 8 个完整黑帧，执行一次 EN_OP，再保持至少 8 个完整黑帧。

## 通道映射假设

按未改 PCB、旧驱动顺序推导每路 4 颗 IC：芯片 0 最靠近 SDI，芯片 3 最远。
旧驱动 x=0 最先发送、x=51 最后发送，因此默认：

- x=0 → 芯片 3 / OUT3；x=51 → 芯片 0 / OUT0。
- 芯片 3 的 OUT4～OUT15 不对应可见像素，一律写零。
- 逻辑 y=0～25 使用 RGB2；y=26～51 使用 RGB1，均对应物理行 0～25。

这来自旧固件的移位次序，尚需屏幕实测确认，不等于原理图验证。
如果逐列测试发现跳列或错序，只修改 `fm6373c_protocol.cpp` 的 `logicalX()` 映射；不要靠修改指令长度补偿。

## 缓冲和错误处理

RGB 影子帧保存逻辑坐标，后台任务自动提取快照，`refreshDisplay()` 提示提交。
`clearScreen()` / `turnOff()` 提交黑色数据但保持 DCLK 和扫描；调光重新编码已有图像。

LCD_CAM 输出 16 位并行字，GDMA 循环发送。每个缓冲只保存 17 组可变时隙，剩余 47 组引用同一份行扫描波形。
常驻 DMA 资源约 148KB，其中约 141KB 波形位于 8MB OPI PSRAM；描述符、固定控制波形及 ISR 状态保留在内部 RAM。RGB 影子帧和快照另用约 16KB 内部 RAM。

实机发现双份波形全部放内部 RAM 会导致 Bluedroid 定时器分配失败并断言复位，因此使用 ESP32-S3 的直接 PSRAM DMA。每个可变波形分段按 64 字节对齐（每块最多 24 个行时隙），提交前调用框架提供的已修补 `Cache_WriteBack_Addr` 同步缓存。PSRAM 分配失败直接报告初始化失败，不挤占蓝牙内存做内部回退。

切换时先恢复目标缓冲自循环，再把旧缓冲尾描述符连接到目标帧头。
只有收到目标帧头的 GDMA EOF，旧缓冲才可重写；绝不依赖猜测延时或停止 DCLK 换帧。
初始化失败或切换超时会关闭输出并打印错误，不回退到 FM6124。
显示初始化失败时主程序不会将待验证 OTA 标记为成功。

## 验证方法

主机测试：

```sh
c++ -std=c++11 -Wall -Wextra -Werror -Ilib/led test/fm6373c_protocol_host.cpp lib/led/fm6373c_protocol.cpp -o /tmp/fm6373c-test
/tmp/fm6373c-test
c++ -std=c++11 -Ilib/led test/brightness_policy_host.cpp -o /tmp/pixelpad-brightness-test
/tmp/pixelpad-brightness-test
```

协议测试使用独立串联移位寄存器接收模型，解码真实分段波形，检查 LE 下降沿、RGB/级联顺序、V1.2 关键寄存器、灰度、空余通道、帧内全部 ROW 脉冲和 DMA 分段边界。

默认关闭诊断模式。临时在 PlatformIO 的 `build_flags` 中加入 `-DFM6373C_DIAGNOSTIC=1`，重新编译烧录后，驱动依次显示逐行、逐列、六路 RGB、色条和灰阶，每阶段 600ms，串口打印当前阶段。完成后移除宏并重新烧录正常固件。

UART0（USB-TTL）115200：初始化打印参数和 DMA 分配大小，每 10 秒打印 DMA 帧率与内部剩余内存。板型默认的原生 USB `Serial` 设置保留，显示日志单独输出到 UART0。

也可以在不重新烧录的情况下发送以换行结尾的命令：`fm test` 启动测试图循环，`fm normal` 恢复应用画面，`fm status` 读取 DMA 计数和当前模式。诊断默认关闭，不修改蓝牙协议。
软件日志确认的是 DMA 活动，无法证明芯片已接受寄存器或屏幕画面正确。

实机验收：冷启动、四角和上下边界、逐行逐列、RGB 纯色、低灰、旋钮调光、动画、蓝牙传图、OTA 期间持续显示。
逻辑分析仪确认 GPIO18 连续 8MHz、LE 指令宽度、VSYNC 至 ROW 间隔、ROW12/ROW4、行地址和 80 时钟行周期。
未连接逻辑分析仪时不得将波形软件测试描述成电气时序实测。

## 第三方代码

LCD_CAM/GDMA 外设配置参考 ESP32 HUB75 LED MATRIX PANEL DMA Display 的 ESP32-S3 后端，原始外设工作来自 Adafruit / PaintYourDragon。
保留的 MIT 许可证见 `LICENSE-HUB75.txt`。本实现不再依赖或修改 PlatformIO 缓存中的 HUB75 库。

## 本次验证记录（2026-09-13）

- 主机协议测试、现有亮度测试及 Clang AddressSanitizer/UndefinedBehaviorSanitizer 检查通过。
- 当前 PlatformIO 目标编译通过，应用约 2.43MB，静态 RAM 约 85KB。
- 已通过 USB-TTL 写入 PSRAM 波形版固件，Flash 数据校验通过。连接的芯片识别为 ESP32-S3，带 8MB PSRAM。
- 实机已输出 FM6373C 初始化成功日志：配置为 8MHz、26 扫、80 clocks/行；初始化后内部可用内存 250808 字节。
- 已修复首次实机测试中因波形占用内部 RAM 导致的 Bluedroid 定时器分配失败和断言复位。供电切换期间另读到 BROWNOUT_RST，不通过禁用欠压检测掩盖它。
- 用户随后反馈灯板已全部点亮，并在后续针对测试图显示的询问中回复“可以了”，记录为现场反馈。USB-TTL 曾断开，工具侧未取得完整测试图过程和持续帧率日志；逻辑分析仪时序、逐项颜色与调光、长期运行及完整 BLE/OTA 回归仍需专项验收。汇总记录见根目录 README。

# FM6373C 颜色曲线修正（3.3.2）

2026-09-14 用户反馈鸿蒙 App 推送图片后，灯板整体颜色发白。

## 诊断与修正

手机日志中抽样的 `sourceRGB` 和 `sent` 相同；App 帧准备过程只重排 RGB 通道，不提升亮度、不添加白色。FM6373C 的旧 `gray()` 则将 sRGB 数值直接线性映射到 PWM。这会使中间色的光输出偏高，是此次泛白的主要软件嫌疑；这项判断不能代替屏幕色度测量。

3.3.2 在最终显示编码处使用 256 项、13 位查表，把 sRGB 转为线性光强，再应用现有亮度比例。参考 [W3C sRGB 转换公式](https://www.w3.org/TR/css-color-4/#color-conversion-code)。例如输入 128 的单通道，正确线性光强约为满量程的 21.6%，旧映射约为 50.2%。

- 黑色、满白和纯 RGB 满量程端点不变，90% 硬件亮度上限仍只应用一次。
- 图片、像素补丁、缓存、待机画面经过同一个显示编码入口。
- RGB 帧缓冲、BLE 数据及帧哈希保持原值，避免 App 和固件重复校正。
- 查表保留 13 位灰阶；刷新循环无新增浮点计算。寄存器、GPIO、扫描和 DMA 时序不变。

## 验证

- 新增独立 sRGB 数学参考测试，旧实现对中间灰断言失败；修正后 256 个输入全部符合曲线误差要求。
- 7 组主机测试通过 Clang AddressSanitizer / UndefinedBehaviorSanitizer；包括独立波形解码、RGB 通道、单调灰阶、亮度零和满量程上限。
- 默认 Wi-Fi/HTTP OTA 与 BLE-only 两个构建通过。
- 实板 ESP32-S3 / FM6373C 已通过 USB 115200 写入 3.3.2，四个写入区段均通过哈希校验；启动日志确认版本 3.3.2，DMA 刷新约 60 FPS。
- 鸿蒙手机使用修复版 App、MTU 512 / 480 字节分包，17:27:47 至 17:28:00 连续 10 次完整 8112 字节图片均收到成功回执，耗时 313～440 ms。
- 用户对同一图片的现场反馈为“明显改善，接近 App”。记录为用户目视确认，不是仪器测色结果。

这不是显示器级的白点和色域校准；LED 光谱、扩散材料、观察环境仍可能造成可见色差。需要用同一图案对照确认用户反馈是否改善。

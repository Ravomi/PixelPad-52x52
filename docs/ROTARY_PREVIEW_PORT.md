# 本地旋钮预览与色号菜单功能集成（3.2.6 / 3.2.7）

目标：当前 FM6124 52×52 RTOS 工程。

## 范围

- 共享 BLE/HTTP OTA 与内容写入所有权、BLE 失败后恢复 Wi-Fi、渐进式接收期限。
- 发布完整画面后做 0～500 ms smoothstep 渐变；中断时以最近显示的中间帧为起点。
- 旋钮保留每个完整步进、半步和反转顺序；队列拥塞重试，通知携带序号。
- PSRAM 缓存当前图纸底图与最多 64 组色号/区域图，由 App 预载后启用本地切换。
- 提供 F6 能力特征、`capabilities`、`input_stats`、`rotary_stats` 与缓存命令。

保留 FM6124 HUB75 驱动、上下半屏映射、引脚、亮度限制、显示配置和当前开机动画。
本地预览依赖 App 完成 `rotary_frame_begin/store/select`，普通 `recv` 只上传画面。

## 验证

主机测试覆盖接收期限、OTA 所有权、画面发布/渐变、实际 FM6124 `LED::present`
与模拟 DMA 交接、旋钮突发/反转/拥塞/跨连接清理，以及当前图纸缓存。
原有协议、亮度、双缓冲脏像素与生命游戏测试继续保留。

实板显示、旋钮触感、App 兼容性以及并发 OTA 需要单独确认，不能由编译成功推断。

## 本地输入与手机通知解耦（尚未实板烧录验证）

原先本地操作虽先计算，但通知入队发生在 renderTask 最终显示提交前，且
BLE TX 拒绝入队会让物理输入 FIFO 停在队首，阻塞后续旋钮操作。
现在每个物理事件直接操作驻留 RAM 缓存，通知进入独立的 64 项 FIFO；
仅在 LED::present 确认已提交显示或画面无需更新后发送。DMA 缓冲尚不能
复用时延后手机通知，本地输入继续处理，不等待手机确认或回传图片。

通知长期积压超过 64 项会丢弃最旧的手机同步事件以保留最新状态，不丢弃
本地操作；input_stats 的 notify_pending / notify_drops 可观察此情况。
连接会话变化时丢弃旧通知，避免跨连接重放。现有缓存会话生命周期未改动。

回归覆盖真实按钮回调和驻留缓存：通知完全不消费时连续 200 次旋转仍逐次
更新色号与目标像素；验证通知 FIFO 顺序、溢出及清理。显示测试确认 DMA
保护期间返回“尚未提交”，缓冲切换后才允许通知。

此修复解决旋钮响应受手机发送队列牵制的问题，不代表已定位安卓手机首次
预载缺失或缓存被清除的原因。OPEN APP / LOAD ART 的根因仍待手机现场日志。

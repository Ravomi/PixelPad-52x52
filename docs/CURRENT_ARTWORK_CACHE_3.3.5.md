# 当前图纸驻留与灯板本地旋钮（3.3.5）

## 行为

打开当前 52×52 图纸/正在拼的分板后，App 先把完整画面和每种颜色的「色号图、选中区域图」存入灯板 PSRAM。所有颜色加载成功后才启用本地旋钮。64 色上限占用 1,046,448 字节；6 色图为 105,456 字节（约 103 KiB）。每个缓存只对应一张当前图纸，不累计图库，不写 Flash 或 NVS；换图、改变预览内容/顺序和连接重建会重新同步。

启用后，输入任务仍以 2 ms 调度保留每个完整步进。渲染任务直接按缓存顺序切换色号，提交显示后才发 `rotary_session` / `rotary_region` 通知。600 ms 后在板上自动切回对应区域，两次切换都保留 200 ms 渐变。手机采用灯板通知中的选中色，既不重复前进，也不回传整帧。手机点选颜色只需短选择命令。

缓存直接使用 App 已准备的 RGB 帧，字体、坐标、镜像、区域掩码和色彩顺序保持一致；输出继续使用 3.3.2 的 sRGB 曲线。

## 同步边界

- 开始缓存即替换上一张图；未齐全时禁止启用本地游标，暂用原传图路径。
- 新启用游标须携带已处理输入序号，避免还有旧通知在路上时漏算一次切换；较旧的手机命令不能覆盖更新的本地旋钮结果。
- 输入通知因 TX 排队重试时，本地切换只执行一次。
- 替换内容后不消费旧图纸通知；旧页面稍后销毁只清理自己 session 的缓存。
- 预览图、模式切换等显式手机画面命令暂停本地游标；单纯调亮度不暂停。
- 缓存接收采用 READY / 有界正文 / 最终 ACK；超时会断开并重建传输状态，不把后续 JSON 当作旧图正文。
- 旧固件和超过本版容量的内容保留既有路径。断电或 BLE 连接会话变化后需重新同步当前图纸。

## 验证

- 10 组 C++ 主机测试通过 Clang ASan / UBSan。新增 10,000 次缓存游标移动、正反向/边界、色号停留、时间回绕、全量就绪和新图替换验证；3.3.4 的 22,154 步输入队列回放仍通过。
- App 67 项相关回归通过；最终缓存清理修正后，38 项缓存、会话及编辑器测试再次通过。新增测试确认完整预加载后本地通知不引起任何帧上传，手机点选走缓存命令。
- 默认 Wi-Fi/OTA 与 BLE-only 构建成功；相关 Dart 分析无问题。
- 鸿蒙 HAP 直接通过 USB 覆盖安装，保留登录与数据；本地签名配置在构建后恢复。

## 实板缓存协议验证

`tools/ble_rotary_cache.py` 在实体 FM6373C 板上先加载一张三色测试图（56,784 字节），确认未选择前未启用本地游标，再进行 9 次缓存选择。每次色号图和停留后的区域图都通过最终 DMA 源帧哈希校验。缓存选择命令 ACK 中位数 42.107 ms，最大 44.791 ms；这不是实体旋钮延迟，实体旋钮已经在灯板本地执行。

旧 session 的清理指令未删除新缓存；开始下一张图后 loaded 归零、count 更新，清理当前图后 count/loaded 均归零。测试没有新增 RX/TX/命令/输入丢弃。最终 3.3.5 应用分区通过 USB 写入与哈希校验。

## 鸿蒙当前图纸验证

最终 USB 安装包 PID 38456，于 19:26:05 协商 MTU 512。当前六色图在 19:26:09～19:26:13 依次完成 1/6 到 6/6 缓存；19:26:13.481 缓存游标启用回执成功，耗时 54 ms。随后实体旋钮序号 5～22 共 18 次连续通知都由手机采用灯板 region，仅同步游标；缓存完成后没有再发出任何 `BLE Image start`。这一段确认「板上切换 → 手机跟随」，不是手机回传整图。

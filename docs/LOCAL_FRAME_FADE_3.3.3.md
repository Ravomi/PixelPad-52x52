# 色号与颜色区域本地过渡（3.3.3）

用户希望色号文字与颜色区域之间平滑渐变，并优先保证响应性能。

## 实现

App 的 52 灯板旋钮预览帧增加可选 200 ms 过渡元数据。读取到设备能力 `frameFade:1` 时，在既有 `recv` 头中附加 `fade_ms:200`，二进制目标帧仍只发送一次。普通图片和未支持此能力的旧设备保留即时显示路径。

灯板收到完整帧后才启动显示任务中的交叉淡化，旧画面在蓝牙接收期间持续显示。动画使用整数 smoothstep 和一份额外 8112 字节源帧；目标保存在既有发布帧中，没有动态帧队列或每帧堆分配。生成的画面继续经过 3.3.2 的 sRGB 显示曲线。

- DMA 扫描持续运行，过渡由 DMA 切换帧同步推进；空闲时退出动画计算。
- 新目标从上一帧实际输出画面开始过渡，中断不会跳回旧目标。
- `fade_ms` 限制在 0～500 ms；省略或为 0 时即时更新。画笔、游戏、待机画面不自动加入过渡。
- 设备 `recv` 回执表示目标已接收并提交；`display_stats.fading=false`、`shown==committed` 和最终 `shown_hash` 才表示过渡完成。
- 新增 `transition_frames` 与 `encode_max_us` 供实板性能验证。
- 数据时隙波形合并行扫描与 RGB 编码，每个 PSRAM 字只写一次；六路位合成展开，减少重复读写。完整混合色测试将优化后的全部数据时隙逐字与原通用编码器比较，结果一致。

## 验证

- 8 组主机测试通过 ASan / UBSan，包括过渡端点、单调性、中途换目标、立即切换、32 位时间回绕，以及既有波形与传输检查。
- 55 项相关 App 测试通过。新测试验证能力缺省兼容、帧数据不可变、单目标仍只需 18 个 BLE 包、发送后仍等待 ACK。
- 默认和 BLE-only 构建通过，相关 Dart 分析及 diff 检查通过。
- USB 烧录 3.3.3 通过哈希校验；保留了已确认的 3.3.2 sRGB 曲线。
- 实板 10 次 200 ms 本地过渡及后续像素补丁全部通过 DMA 源帧哈希验证，结束时 `shown==committed`、`fading=false`；RX/TX/命令/输入队列均无新增丢包。
- 同一测试前后，编码最大墙钟耗时从 25334 us 降为 19287 us，下降约 23.9%；十次过渡的中间帧从 66 增至 83，平均每 200 ms 约 8 帧。该耗时包含 RTOS 抢占，不等于纯 CPU 计时；DMA 扫描持续约 60 FPS，不应把扫描 FPS 等同于过渡生成 FPS。
- 优化版图片 ACK 中位数 194.962 ms，最大 255.431 ms；从发送开始到最终 DMA 哈希确认约 390～481 ms，包含图片传输、200 ms 过渡和查询轮询。
- 鸿蒙手机最终安装包实测：17:52:31 协商 MTU 512，17:53:12 图片日志确认 `packetSize=480 fadeMs=200`，随后收到设备 ACK。说明能力发现与 App 过渡元数据已贯通。
